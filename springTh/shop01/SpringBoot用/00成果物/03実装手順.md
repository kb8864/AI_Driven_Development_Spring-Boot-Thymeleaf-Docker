# 商品管理アプリ 実装手順

[01要件定義.md](01要件定義.md) と [02設計仕様.md](02設計仕様.md) に基づく実装手順を、ステップバイステップで示す。

- 本書は**手順のみ**を記載する（実装コードおよび動作確認手順は含まない）。
- 各クラスの具体的な仕様（メソッド、SQL、バリデーション、画面項目）は [02設計仕様.md](02設計仕様.md) を参照すること。
- SpringBoot プロジェクトは作成済みのため、プロジェクト生成の手順は含まない。

実装に着手する前に、以下を確認する。

| No. | 確認内容 |
| --- | --- |

| 0-5 | [02設計仕様.md](02設計仕様.md) の「10. 実装前の確認事項」で挙げた `spring-boot-starter-web` の追加可否について、了承が得られていること |

## 実装の全体像

設定 → 下位レイヤ → 上位レイヤ → 画面、の順に進める。下位から積み上げることで、上位を書く時点で呼び出し先が確定している状態を保つ。

```
【第1部】設定           STEP 1 ─ 3   pom.xml / application.properties / messages.properties
【第2部】データの入れ物   STEP 4 ─ 6   パッケージ作成 / entity / form
【第3部】DBアクセス      STEP 7 ─ 8   dao（IF） / dao.impl
【第4部】業務ロジック     STEP 9 ─ 11  service（IF） / service.impl / util
【第5部】画面制御        STEP 12      controller
【第6部】画面           STEP 13 ─ 17 templates / static
【第7部】仕上げ         STEP 18 ─ 19 ビルド / 成果物チェック
```

# 【第1部】設定（最優先）

設定を最初に完了させる。ここが誤っているとアプリが起動せず、以降の実装が一切検証できないため、**STEP 1 と STEP 2 は他のどの作業よりも先に行う**。

## STEP 1. pom.xml に依存関係を追加する

**対象ファイル**：`shop01/pom.xml`

### 手順

1. `<dependencies>` 要素を開く。
2. 既存の `spring-boot-starter` / `spring-boot-docker-compose` / `spring-boot-starter-test` はそのまま残す。
3. [02設計仕様.md](02設計仕様.md) 「3-1. pom.xml に追記する依存関係」に記載の**5件**を `<dependencies>` の中へ追記する。
   - `spring-boot-starter-jdbc`
   - `spring-boot-starter-thymeleaf`
   - `spring-boot-starter-validation`
   - `spring-boot-devtools`（`<scope>runtime</scope>` / `<optional>true</optional>`）
   - `mysql-connector-j`（`<scope>runtime</scope>`）
4. さらに `spring-boot-starter-web` を追記する。
   - 理由：`spring-boot-starter-thymeleaf` には Spring MVC と組込み Tomcat が含まれず、これがないとアプリが Web アプリケーションとして起動しない（[02設計仕様.md](02設計仕様.md) 3-1 参照）。
5. `<version>` は書かない。すべて親 POM（`spring-boot-starter-parent` 4.1.1）がバージョンを管理する。

### 完了の目安

- [ ] `<dependencies>` に合計9件の `<dependency>` が並んでいる
- [ ] 依存関係の解決（Maven のリロード／`./mvnw dependency:resolve`）がエラーなく終わる
- [ ] `spring-webmvc`・`spring-jdbc`・`thymeleaf-spring6`・`mysql-connector-j` が依存ツリーに現れる

### つまずきやすい点

- `<dependencies>` と `<dependencyManagement>` を取り違えない。追記先は `<dependencies>`。
- 依存を追加しただけでは IDE に反映されないことがある。Maven プロジェクトの再読み込みを行う。

## STEP 2. application.properties を設定する

**対象ファイル**：`shop01/src/main/resources/application.properties`

### 手順

1. 既存の `spring.application.name=shop01` は残す。
2. [02設計仕様.md](02設計仕様.md) 「3-2. application.properties」の内容を追記する。設定する値は次のとおり（[21DDL.sql](../20DB/21DDL.sql) から取得した値）。

   | プロパティ | 値 | 取得元 |
   | --- | --- | --- |
   | `spring.datasource.driver-class-name` | `com.mysql.cj.jdbc.Driver` | 固定 |
   | `spring.datasource.url` | `jdbc:mysql://localhost:3306/shop` | DDL の `CREATE DATABASE shop` |
   | `spring.datasource.username` | `suser` | DDL の `CREATE USER 'suser'@'%'` |
   | `spring.datasource.password` | `spass` | DDL の `IDENTIFIED BY 'spass'` |

3. 開発用に以下を追記する。
   - `spring.thymeleaf.cache=false`（テンプレート修正の即時反映）
   - `spring.messages.basename=messages` / `spring.messages.encoding=UTF-8`（STEP 3 で作るメッセージ定義の読み込み）

### 完了の目安

- [ ] `spring.datasource.*` の4項目が設定されている
- [ ] URL のデータベース名が `shop` になっている
- [ ] ユーザー名・パスワードが DDL の記述と一致している

### つまずきやすい点

- プロパティファイルでは値をクォートで囲まない（`'spass'` ではなく `spass`）。
- 値の前後に余分な空白を入れない。末尾スペースはそのまま値に含まれる。
- 起動時に docker-compose 関連のエラーが出る場合は、`spring.docker.compose.enabled=false` を追記して無効化する（[compose.yaml](../../compose.yaml) は空定義のため使用しない）。

## STEP 5. entity/Item.java を作成する

**対象ファイル**：`entity/Item.java`（新規）

### 手順

1. `item` テーブルの1行を表すクラスを作る。フィールドは `id`(String) / `name`(String) / `price`(Integer) / `stock`(Integer)。
2. **引数なしコンストラクタ**を用意する。`BeanPropertyRowMapper` がこれを使ってインスタンスを生成するため必須。
3. 全フィールドの getter / setter を用意する。`BeanPropertyRowMapper` は setter 経由で値を設定する。
4. 全フィールドを受け取るコンストラクタも用意する（任意。生成の利便のため）。
5. `@Entity` / `@Table` / `@Id` は**付けない**（設計上の禁止アノテーション）。

### 完了の目安

- [ ] クラスにアノテーションが1つも付いていない
- [ ] 引数なしコンストラクタがある
- [ ] フィールド名が DB のカラム名と一致している（今回はすべて1単語のため変換不要）

### つまずきやすい点

- 引数ありコンストラクタだけを定義すると、引数なしコンストラクタが自動生成されなくなる。両方を明示的に書く。
- `price` / `stock` を `int`（プリミティブ型）にすると、未入力を `null` として扱えず `@NotNull` が機能しない。**`Integer` を使う**。

## STEP 6. form/ItemForm.java を作成する

**対象ファイル**：`form/ItemForm.java`（新規）

### 手順

1. 画面の入力値を受ける4フィールド（`id` / `name` / `price` / `stock`）を持つクラスを作る。登録画面・更新画面で共用する。
2. 引数なしコンストラクタと getter / setter を用意する（Spring が入力値をバインドするために必要）。
3. [02設計仕様.md](02設計仕様.md) 「5-2. バリデーション定義」の表に従い、各フィールドにバリデーションアノテーションを付ける。
   - `id`：`@NotBlank` / `@Size(max = 20)`
   - `name`：`@NotBlank` / `@Size(max = 100)`
   - `price`：`@NotNull` / `@Min(0)` / `@Max(99999999)`
   - `stock`：`@NotNull` / `@Min(0)` / `@Max(99999999)`
4. 各アノテーションの `message` 属性に、設計書の表にある日本語メッセージを指定する。
5. import 元は `jakarta.validation.constraints.*`（`javax` ではない）。

### 完了の目安

- [ ] 4フィールドすべてにバリデーションアノテーションが付いている
- [ ] メッセージがすべて日本語で指定されている
- [ ] import が `jakarta.validation.constraints` 配下になっている

### つまずきやすい点

- 商品IDの**重複チェックはここでは行わない**。DB を参照する必要があるため、Service で判定して Controller がエラーとして積む（STEP 10・12）。
- `@NotBlank` は String 専用。数値には `@NotNull` を使う。

## STEP 8. dao/impl/ItemDaoImpl.java を作成する

**対象ファイル**：`dao/impl/ItemDaoImpl.java`（新規）

### 手順

1. `ItemDao` を `implements` するクラスを作り、`@Repository` を付ける。
2. `NamedParameterJdbcTemplate` 型のフィールドを `private final` で宣言する。
3. このフィールドを引数に取るコンストラクタを1つだけ定義する。
   - コンストラクタが1つだけの場合、Spring が自動的に注入する。**`@Autowired` は書かない**（禁止アノテーション）。
4. SQL は `private static final String` の定数として、[02設計仕様.md](02設計仕様.md) 「5-4」の表どおりに定義する。
   - パラメータは必ず `:id` のような**名前付きパラメータ**で書く。文字列連結は行わない。
5. 各メソッドを実装する。

   | メソッド | 使用する API | パラメータの渡し方 |
   | --- | --- | --- |
   | `findAll` | `query(sql, パラメータ, new BeanPropertyRowMapper<>(Item.class))` | 空の `MapSqlParameterSource` |
   | `findById` | 同上 | `MapSqlParameterSource("id", id)` |
   | `insert` | `update(sql, パラメータ)` | `BeanPropertySqlParameterSource(item)` |
   | `update` | `update(sql, パラメータ)` | `BeanPropertySqlParameterSource(item)` |
   | `delete` | `update(sql, パラメータ)` | `MapSqlParameterSource("id", id)` |
   | `countById` | `queryForObject(sql, パラメータ, Integer.class)` | `MapSqlParameterSource("id", id)` |

6. `findById` は `queryForObject` を使わず、`query` で `List` を受け取り、**空なら `null` を返す**実装にする。
   - `queryForObject` は該当0件で `EmptyResultDataAccessException` を投げるため。
7. `RowMapper` は手動実装せず、必ず `new BeanPropertyRowMapper<>(Item.class)` を使う。

### 完了の目安

- [ ] `@Repository` が付いている
- [ ] `@Autowired` を使わずコンストラクタで `NamedParameterJdbcTemplate` を受け取っている
- [ ] SQL 中に文字列連結（`+` による値の埋め込み）が1箇所もない
- [ ] `RowMapper` を実装したクラス・匿名クラスが存在しない
- [ ] `findById` が該当なしで例外を投げず `null` を返す

### つまずきやすい点

- import するのは `NamedParameterJdbcTemplate`（`org.springframework.jdbc.core.namedparam`）。`JdbcTemplate` と間違えると `:id` 形式が使えない。
- `BeanPropertySqlParameterSource` は Entity のフィールド名と SQL のパラメータ名（`:name` など）が一致している必要がある。
- `update` の SQL の SET 句に `id` を含めない（商品IDは変更不可）。

## STEP 10. service/impl/ItemServiceImpl.java を作成する

**対象ファイル**：`service/impl/ItemServiceImpl.java`（新規）

### 手順

1. `ItemService` を `implements` するクラスを作り、`@Service` を付ける。
2. `ItemDao` 型のフィールドを `private final` で宣言し、コンストラクタで受け取る（`@Autowired` は書かない）。
   - **フィールドの型は実装クラス `ItemDaoImpl` ではなく、インターフェース `ItemDao`** とする。
3. 参照系（`findAll` / `findById`）は DAO をそのまま呼ぶ。
4. `existsById` は `dao.countById(id) > 0` で判定する。
5. `register` / `update` / `delete` に `@Transactional`（`org.springframework.transaction.annotation`）を付ける。
6. Form から Entity への詰め替えを行う `private Item toEntity(ItemForm form)` を用意し、`register` / `update` から呼ぶ。
7. `update` / `delete` は DAO の戻り値（更新件数）が `1` 以上かどうかで `boolean` を返す。
   - 更新件数0は「対象が存在しなかった」を意味し、Controller 側でエラーメッセージ表示に使う。
8. `register` は重複チェック済みの前提で呼ばれるため、`insert` の件数が 1 なら true を返す。

### 完了の目安

- [ ] `@Service` が付いている
- [ ] 依存フィールドの型がインターフェース（`ItemDao`）になっている
- [ ] 更新系3メソッドに `@Transactional` が付いている
- [ ] 更新件数0を `false` として返している

### つまずきやすい点

- `@Transactional` は `jakarta.transaction` ではなく `org.springframework.transaction.annotation` を import する。
- 画面向けの文言（メッセージ）は Service に持たせない。定数は `util`、表示判断は Controller の担当。

# 【第5部】画面制御

## STEP 12. controller/ItemController.java を作成する

**対象ファイル**：`controller/ItemController.java`（新規）

### 手順

1. クラスに `@Controller` を付ける。**`@RequestMapping` は使わない**（禁止アノテーション）ため、クラスレベルの共通パス指定は行わない。
2. `ItemService` 型のフィールドをコンストラクタで受け取る（`@Autowired` は書かない）。
3. [02設計仕様.md](02設計仕様.md) 「5-7」の表に従い、7つのメソッドを実装する。各メソッドの `@GetMapping` / `@PostMapping` には**フルパス**を書く。

   | 順序 | メソッド | マッピング |
   | --- | --- | --- |
   | 1 | `root` | `@GetMapping("/")` |
   | 2 | `list` | `@GetMapping("/items")` |
   | 3 | `addForm` | `@GetMapping("/items/add")` |
   | 4 | `add` | `@PostMapping("/items/add")` |
   | 5 | `editForm` | `@GetMapping("/items/edit/{id}")` |
   | 6 | `edit` | `@PostMapping("/items/edit")` |
   | 7 | `delete` | `@PostMapping("/items/delete/{id}")` |

4. 画面名・リダイレクト先・メッセージは、文字列を直書きせず `AppConst` の定数を使う。
5. 登録処理（`add`）の順序を守る。
   1. `@Validated`（または `@Valid`）付きの `ItemForm` と `BindingResult` を受け取る
   2. `bindingResult.hasErrors()` が true なら登録画面を再表示
   3. `itemService.existsById(form.getId())` が true なら `bindingResult.rejectValue("id", null, AppConst.MSG_DUPLICATE_ID)` でエラーを積み、登録画面を再表示
   4. どちらも通れば `itemService.register(form)` を実行
   5. `RedirectAttributes#addFlashAttribute` で完了メッセージを渡し、一覧へリダイレクト
6. 更新画面表示（`editForm`）では、`findById` の結果が `null` の場合に一覧へリダイレクトし、`MSG_NOT_FOUND` を渡す。取得できた場合は `Item` を `ItemForm` に詰め替えて Model に格納する。
7. 更新（`edit`）・削除（`delete`）は、Service の戻り値が `false` のとき `MSG_NOT_FOUND` をエラーメッセージとして渡す。
8. 登録・更新・削除の完了後は必ず `redirect:` で一覧へ戻す（PRG パターン）。入力エラー時のみ、テンプレート名をそのまま返す。

### 完了の目安

- [ ] `@RequestMapping` / `@Autowired` を1箇所も使っていない
- [ ] 7メソッドすべてのパスが設計書と一致している
- [ ] `BindingResult` の引数が、`@Validated` を付けた `ItemForm` の**直後**に宣言されている
- [ ] 更新系の完了後がすべて `redirect:` になっている
- [ ] 画面名・メッセージが `AppConst` 経由になっている

### つまずきやすい点

- `BindingResult` を Form の直後に置かないと、バインドエラーが例外として送出される。引数の順序は必ず `(@Validated ItemForm form, BindingResult result, ...)`。
- 入力エラーで画面を再表示するときに `redirect:` を使うと、入力値とエラーが失われる。テンプレート名を直接返す。
- Model の属性名は、テンプレート側の `th:object="${itemForm}"` と一致させる。`@Validated ItemForm itemForm` と宣言すればクラス名の先頭小文字（`itemForm`）で自動的に Model に入る。
- `@GetMapping("/items/add")` と `@PostMapping("/items/add")` はパスが同じでもメソッドが異なるため共存できる。

## STEP 16. templates/item/edit.html を作成する

**対象ファイル**：`src/main/resources/templates/item/edit.html`（新規）

### 手順

1. `<form th:action="@{/items/edit}" th:object="${itemForm}" method="post">` でフォームを開く。パスに `{id}` は含めない（値は hidden で送る）。
2. 商品IDは**変更不可**とする。[02設計仕様.md](02設計仕様.md) 「6-6」の書き分けに従い、2つの要素を置く。

   | 要素 | 役割 | 書き方 |
   | --- | --- | --- |
   | hidden | 値の送信 | `<input type="hidden" th:field="*{id}">` |
   | 表示用テキスト | 表示のみ | `th:value="*{id}"` ＋ `readonly`、`name` 属性なし |

   - 両方に `th:field` を書くと HTML の `id` 属性が重複するため、表示用には `th:value` を使う。
   - `disabled` は使わない（値が送信されなくなる）。
3. 商品名・値段・在庫は登録画面と同じ構成（`th:field` ＋ `th:errors`）で配置する。
4. 各項目にエラー表示欄を置く。
5. 「更新」ボタン（submit）と「戻る」リンク（`@{/items}`）を配置する。

### 完了の目安

- [ ] 商品ID が編集できない状態になっている
- [ ] 商品ID の値がサーバーへ送信される（hidden がある）
- [ ] HTML の `id` 属性が重複していない（開発者ツールで警告が出ない）
- [ ] 画面を開いた時点で既存の値が入力欄に表示される

### つまずきやすい点

- 入力エラーで画面を再表示したとき、hidden がないと商品ID が失われて更新できなくなる。
- `readonly` の入力欄は値が送信されるが、`disabled` にすると**送信されない**。
