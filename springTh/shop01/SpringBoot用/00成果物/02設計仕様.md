# 商品管理アプリ 設計仕様

[01要件定義.md](01要件定義.md) を実現するための技術設計をまとめる。

---

## 1. 開発環境・使用技術

| 区分 | 内容 |
| --- | --- |
| フレームワーク | Spring Boot 4.1.1 |
| 言語 | Java 21 |
| ビルドツール | Maven（mvnw 同梱） |
| 画面テンプレート | Thymeleaf |
| DBアクセス | Spring JDBC（NamedParameterJdbcTemplate） |
| 入力チェック | Jakarta Bean Validation（spring-boot-starter-validation） |
| データベース | MySQL 9 |
| 基底パッケージ | `com.example.shop01` |

### 1-1. 設計上の制約（遵守事項）

- 以下のアノテーションは**使用しない**。
  - `@WebServlet` / `@Entity` / `@Table` / `@Id` / `@RequestMapping` / `@Autowired`
- DI はすべて**コンストラクタインジェクション**で行う（`@Autowired` を書かなくても、単一コンストラクタなら Spring が自動的に注入する）。
- URL のマッピングは `@RequestMapping` を使わず、`@GetMapping` / `@PostMapping` にフルパスを指定する（クラスレベルの共通パス指定は行わない）。
- Entity は ORM のアノテーションを付けない素の Java クラス（POJO）とする。
- SQL は文字列連結せず、**必ず名前付きパラメータ**（`:id` 形式）でバインドする（SQLインジェクション対策）。
- `RowMapper` は手動実装せず、`new BeanPropertyRowMapper<>(Item.class)` を使用する。
- DB のカラム名はスネークケース、Java のフィールド名はキャメルケースとする。SELECT 時に名前が一致しない場合は SQL 側で `AS` を用いてキャメルケースへ寄せる。
  - 今回の `item` テーブルは `id` / `name` / `price` / `stock` と単語1つのため、`AS` は不要。

- `<version>` は記載しない。すべて親 POM（`spring-boot-starter-parent` 4.1.1）が管理する。
- 既存の `spring-boot-starter` / `spring-boot-docker-compose` / `spring-boot-starter-test` はそのまま残す。

#### 【要確認】spring-boot-starter-web の追加が必要

上記5件に加えて、**`spring-boot-starter-web` の追加が必須**と判断した。理由は次のとおり。

- 現在の pom.xml の依存は `spring-boot-starter` のみで、Web（Spring MVC / 組込み Tomcat）が含まれていない。
- `spring-boot-starter-thymeleaf` 4.0.6 の依存を確認したところ、含まれるのは `spring-boot-starter` と `spring-boot-thymeleaf` のみで、Web は含まれない。
- Web がないと `@Controller` も画面表示も動作せず、アプリが起動直後に終了してしまう。

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

※ 指示にない依存の追加となるため、実装前に本項の可否をご確認いただきたい。

pom.xml に `spring-boot-docker-compose` が含まれるが、[compose.yaml](../../compose.yaml) は `services: {}` の空定義であり、起動するコンテナはない。MySQL はローカル（localhost:3306）の稼働中インスタンスへ接続する。起動時に支障が出る場合は `spring.docker.compose.enabled=false` を追記して無効化する。

## 4. アプリケーション構成

### 4-1. レイヤ構成

```
ブラウザ
   │  HTTP（GET / POST）
   ▼
Controller ── Form（画面の入力値／バリデーション）
   │
   ▼
Service（IF） ─→ ServiceImpl（業務ロジック・トランザクション）
   │
   ▼
Dao（IF） ─→ DaoImpl（NamedParameterJdbcTemplate で SQL 実行）
   │
   ▼
MySQL（item テーブル） ── Entity（1行 ＝ 1オブジェクト）
```

- **Controller**：リクエストの受け取り、Form の入力チェック、画面（テンプレート名）の決定。
- **Service**：業務ルール（ID 重複チェック、対象存在チェックなど）。Form → Entity の変換もここで行う。
- **Dao**：SQL の実行のみを担当。業務判断は持たない。
- **Entity**：DB の1行に対応する入れ物。`BeanPropertyRowMapper` が使えるよう、引数なしコンストラクタと getter/setter を持つ。
- **Form**：画面の入力項目に対応する入れ物。バリデーションアノテーションを付ける。
- **util**：画面名・URL・メッセージなどの定数置き場。

### 4-2. ディレクトリ構成

```

└─ src/main/
   ├─ java/com/example/shop01/
   │  ├─ Shop01Application.java          … 起動クラス（既存・変更なし）
```

## 5. クラス設計

### 5-1. entity / Item.java

DB の1行を表す POJO。ORM アノテーションは付けない。

| フィールド | 型 | 対応カラム |
| --- | --- | --- |
| id | String | id |
| name | String | name |
| price | Integer | price |
| stock | Integer | stock |

- 引数なしコンストラクタ（`BeanPropertyRowMapper` が使用するため必須）
- 全項目の getter / setter（`BeanPropertyRowMapper` は setter 経由で値を設定する）
- 全項目を受け取るコンストラクタ（任意。生成の利便のため）
- `price` / `stock` は `int` ではなく **`Integer`**（未入力を `null` として扱うため）

### 5-2. form / ItemForm.java

登録画面・更新画面で共用する。更新時は `id` を hidden で保持し、画面上は変更不可（表示のみ）とする。

| フィールド | 型 | 画面項目 |
| --- | --- | --- |
| id | String | 商品ID |
| name | String | 商品名 |
| price | Integer | 値段 |
| stock | Integer | 在庫 |

#### バリデーション定義

| フィールド | アノテーション | メッセージ |
| --- | --- | --- |
| id | `@NotBlank` | 商品IDを入力してください |
| id | `@Size(max = 20)` | 商品IDは20文字以内で入力してください |
| name | `@NotBlank` | 商品名を入力してください |
| name | `@Size(max = 100)` | 商品名は100文字以内で入力してください |
| price | `@NotNull` | 値段を入力してください |
| price | `@Min(0)` | 値段は0以上で入力してください |
| price | `@Max(99999999)` | 値段が大きすぎます |
| stock | `@NotNull` | 在庫を入力してください |
| stock | `@Min(0)` | 在庫は0以上で入力してください |
| stock | `@Max(99999999)` | 在庫が大きすぎます |

- import 元は `jakarta.validation.constraints.*`（`javax` ではない）。
- `@Max` の上限は MySQL の `INT` 最大値（2147483647）を超えないための保険。
- 数値項目に文字を入力した場合は Spring が型変換エラー（`typeMismatch`）を返すため、`messages.properties` に日本語メッセージを定義する。

```properties
typeMismatch.java.lang.Integer=数値で入力してください
typeMismatch=入力形式が正しくありません
```

- **商品IDの重複チェック**はアノテーションでは行えないため、Service で判定し、Controller が `BindingResult#rejectValue` でエラーとして積む（アノテーション制約と同じ見た目で画面に表示される）。

### 5-3. dao / ItemDao.java（インターフェース）

| メソッド | 戻り値 | 内容 |
| --- | --- | --- |
| `findAll()` | `List<Item>` | 全商品を商品ID の昇順で取得 |
| `findById(String id)` | `Item` | 商品ID で1件取得。該当なしは `null` |
| `insert(Item item)` | `int` | 1件登録。更新件数を返す |
| `update(Item item)` | `int` | 1件更新。更新件数を返す |
| `delete(String id)` | `int` | 1件削除。更新件数を返す |
| `countById(String id)` | `int` | 指定 ID の件数（重複チェック用） |

- 更新系の戻り値を `int`（更新件数）とするのは、対象が存在したかを呼び出し側で判定するため。

### 5-4. dao/impl / ItemDaoImpl.java

- `@Repository` を付与。
- `NamedParameterJdbcTemplate` を `private final` フィールドで保持し、コンストラクタで受け取る（`@Autowired` は書かない）。
- import は `org.springframework.jdbc.core.namedparam.NamedParameterJdbcTemplate`（`JdbcTemplate` と取り違えない）。

#### 実行する SQL

SQL は `private static final String` の定数として定義する。

| メソッド | SQL |
| --- | --- |
| findAll | `SELECT id, name, price, stock FROM item ORDER BY id` |
| findById | `SELECT id, name, price, stock FROM item WHERE id = :id` |
| insert | `INSERT INTO item (id, name, price, stock) VALUES (:id, :name, :price, :stock)` |
| update | `UPDATE item SET name = :name, price = :price, stock = :stock WHERE id = :id` |
| delete | `DELETE FROM item WHERE id = :id` |
| countById | `SELECT COUNT(*) FROM item WHERE id = :id` |

- `update` の SET 句に `id` を含めない（商品IDは変更不可のため）。

#### パラメータと API の対応

| メソッド | 使用する API | パラメータ |
| --- | --- | --- |
| findAll | `query(sql, param, new BeanPropertyRowMapper<>(Item.class))` | 空の `MapSqlParameterSource` |
| findById | 同上 | `MapSqlParameterSource("id", id)` |
| insert | `update(sql, param)` | `BeanPropertySqlParameterSource(item)` |
| update | `update(sql, param)` | `BeanPropertySqlParameterSource(item)` |
| delete | `update(sql, param)` | `MapSqlParameterSource("id", id)` |
| countById | `queryForObject(sql, param, Integer.class)` | `MapSqlParameterSource("id", id)` |

- `findById` は `queryForObject` を使わない。該当0件で `EmptyResultDataAccessException` を投げるため、`query(...)` で `List` を受け取り、空なら `null` を返す。

```java
List<Item> list = jdbcTemplate.query(SQL, param, new BeanPropertyRowMapper<>(Item.class));
return list.isEmpty() ? null : list.get(0);
```

### 5-5. service / ItemService.java（インターフェース）

| メソッド | 戻り値 | 内容 |
| --- | --- | --- |
| `findAll()` | `List<Item>` | 一覧表示用に全商品を取得 |
| `findById(String id)` | `Item` | 1件取得。該当なしは `null` |
| `existsById(String id)` | `boolean` | 商品ID の重複判定（登録時に使用） |
| `register(ItemForm form)` | `boolean` | 新規登録。登録できたら true |
| `update(ItemForm form)` | `boolean` | 更新。対象なし（更新件数0）なら false |
| `delete(String id)` | `boolean` | 削除。対象なし（削除件数0）なら false |

- 引数は `ItemForm`、戻り値は `Item`。Form → Entity の変換は Service の役割とする。

### 5-6. service/impl / ItemServiceImpl.java

- `@Service` を付与。更新系（`register` / `update` / `delete`）に `@Transactional`（`org.springframework.transaction.annotation`）を付与。
- `ItemDao` を `private final` フィールドで保持し、コンストラクタで受け取る（`@Autowired` は書かない）。フィールドの型は実装クラスではなく**インターフェース**とする。
- `existsById` は `dao.countById(id) > 0` で判定する。
- Form → Entity の詰め替えを `private Item toEntity(ItemForm form)` として持ち、`register` / `update` から呼ぶ。
- `update` / `delete` は DAO の戻り値（更新件数）が 1 以上かで `boolean` を返す。更新件数0は「対象が存在しなかった」を意味する。
- `register` は重複チェック済みの前提で呼ばれるため、`insert` の件数が 1 なら true を返す。
- 画面向けの文言（メッセージ）は Service に持たせない。定数は `util`、表示判断は Controller の担当とする。

### 5-7. controller / ItemController.java

- `@Controller` を付与。**`@RequestMapping` は使わない**ため、クラスレベルの共通パス指定は行わず、各メソッドにフルパスを書く。
- `ItemService` を `private final` フィールドで保持し、コンストラクタで受け取る（`@Autowired` は書かない）。
- 画面名・リダイレクト先・メッセージは文字列を直書きせず `AppConst` の定数を使う。

| No. | メソッド | HTTP / パス | 処理概要 | 戻り |
| --- | --- | --- | --- | --- |
| 1 | `root()` | GET `/` | 一覧へ転送 | `redirect:/items` |
| 2 | `list(Model)` | GET `/items` | 全商品を取得し `items` として Model に格納 | `item/list` |
| 3 | `addForm(ItemForm)` | GET `/items/add` | 空の Form を渡して登録画面を表示 | `item/add` |
| 4 | `add(@Validated ItemForm, BindingResult, RedirectAttributes)` | POST `/items/add` | 入力チェック → ID重複チェック → 登録 | OK: `redirect:/items` / NG: `item/add` |
| 5 | `editForm(@PathVariable String id, Model, RedirectAttributes)` | GET `/items/edit/{id}` | 対象を取得して Form に詰め、更新画面を表示 | 有: `item/edit` / 無: `redirect:/items` |
| 6 | `edit(@Validated ItemForm, BindingResult, RedirectAttributes)` | POST `/items/edit` | 入力チェック → 更新 | OK: `redirect:/items` / NG: `item/edit` |
| 7 | `delete(@PathVariable String id, RedirectAttributes)` | POST `/items/delete/{id}` | 対象を削除 | `redirect:/items` |

#### 登録処理（add）の順序

1. `bindingResult.hasErrors()` が true なら登録画面を再表示
2. `itemService.existsById(form.getId())` が true なら `bindingResult.rejectValue("id", null, AppConst.MSG_DUPLICATE_ID)` でエラーを積み、登録画面を再表示
3. どちらも通れば `itemService.register(form)` を実行
4. `RedirectAttributes#addFlashAttribute` で完了メッセージを渡し、一覧へリダイレクト

#### 設計上のポイント

- 登録・更新・削除の完了後は必ず `redirect:` で一覧へ戻す（PRG パターン）。ブラウザの再読み込みによる二重登録を防ぐ。
- リダイレクト先へ渡すメッセージは `RedirectAttributes#addFlashAttribute` を使用する（属性名：`successMessage` / `errorMessage`）。
- 入力エラーで画面を再表示する場合は `redirect` せず、テンプレート名をそのまま返す（入力値とエラーを保持するため）。
- `@Validated`（または `@Valid`）を付けた Form の**直後**に `BindingResult` を宣言する（順序が逆だと例外になる）。
- Model の属性名はテンプレートの `th:object="${itemForm}"` と一致させる。引数を `ItemForm itemForm` と宣言すれば、クラス名の先頭小文字（`itemForm`）で自動的に Model に入る。
- `editForm` は `findById` が `null` のとき、一覧へリダイレクトして `MSG_NOT_FOUND` を渡す。
- `edit` / `delete` は Service の戻り値が false のとき `MSG_NOT_FOUND` をエラーメッセージとして渡す。

### 5-8. util / AppConst.java

画面名・リダイレクト先・メッセージ文言の定数を集約する。`final class` とし、`private` コンストラクタでインスタンス化を禁止する。

| 定数名 | 値 |
| --- | --- |
| `VIEW_ITEM_LIST` | `"item/list"` |
| `VIEW_ITEM_ADD` | `"item/add"` |
| `VIEW_ITEM_EDIT` | `"item/edit"` |
| `REDIRECT_ITEM_LIST` | `"redirect:/items"` |
| `MSG_REGISTERED` | `"商品を登録しました。"` |
| `MSG_UPDATED` | `"商品を更新しました。"` |
| `MSG_DELETED` | `"商品を削除しました。"` |
| `MSG_DUPLICATE_ID` | `"この商品IDは既に登録されています。"` |
| `MSG_NOT_FOUND` | `"対象の商品が見つかりませんでした。"` |
| `ATTR_SUCCESS` | `"successMessage"` |
| `ATTR_ERROR` | `"errorMessage"` |

- 画面名の値はテンプレートの配置パスと一致させる（例：`item/list` ↔ `templates/item/list.html`）。


### 6-3. common/layout.html

- `<html xmlns:th="http://www.thymeleaf.org">` を宣言する。
- `th:fragment` で共通部品を定義し、各画面から `th:replace` で読み込む。
  - `header`：アプリ名（商品管理）の見出し
  - `messages`：`successMessage` / `errorMessage` の表示エリア（それぞれ `th:if` で存在時のみ表示）
  - `footer`：フッター
- 追加ライブラリ（thymeleaf-layout-dialect）は使用しない。標準の `th:fragment` / `th:replace` のみで構成する。

### 6-4. item/list.html（商品一覧画面）

| 表示項目 | 内容 |
| --- | --- |
| 見出し | 「商品一覧」 |
| メッセージ | 登録／更新／削除の完了メッセージ、エラーメッセージ |
| 「新規登録」ボタン | `@{/items/add}` へのリンク |
| 一覧テーブル | 商品ID / 商品名 / 値段 / 在庫 / 操作 |
| 「更新」ボタン（各行） | `@{/items/edit/{id}(id=${item.id})}` へのリンク |
| 「削除」ボタン（各行） | `@{/items/delete/{id}(id=${item.id})}` への POST フォーム |
| 0件時の表示 | 「商品がありません。」 |

- 繰り返しは `th:each="item : ${items}"`、0件判定は `th:if="${#lists.isEmpty(items)}"` を使用する。
- 値段は `${#numbers.formatInteger(item.price, 1, 'COMMA')}` で3桁区切り表示し、末尾に「円」を付ける。
- URL は必ず `@{...}` 形式で書く。パス変数付きは `@{/items/edit/{id}(id=${item.id})}` と書き、文字列連結にしない。
- 削除は GET リンクではなく **POST フォーム**とする（URL の直打ちやブラウザの先読みによる誤削除を防ぐため）。フォームに `data-confirm-delete` 属性を付け、確認ダイアログの対象とする。
- CSS は `th:href="@{/css/style.css}"`、JS は `th:src="@{/js/common.js}"` で参照する。

### 6-5. item/add.html（商品登録画面）

`<form th:action="@{/items/add}" th:object="${itemForm}" method="post">`

| 入力項目 | 部品 | 備考 |
| --- | --- | --- |
| 商品ID | `type="text"` | 必須・20文字以内 |
| 商品名 | `type="text"` | 必須・100文字以内 |
| 値段 | `type="number"` / `min="0"` | 必須・0以上 |
| 在庫 | `type="number"` / `min="0"` | 必須・0以上 |

- 各入力欄は `th:field="*{id}"` のように `th:field` でバインドする（`name` / `id` / `value` は自動生成されるため併記しない）。
- 各項目の直下に `th:if="${#fields.hasErrors('id')}"` ＋ `th:errors="*{id}"` でエラーメッセージを表示する。
- ボタン：「登録」（submit）、「戻る」（`@{/items}` へのリンク）。

### 6-6. item/edit.html（商品更新画面）

`<form th:action="@{/items/edit}" th:object="${itemForm}" method="post">`（パスに `{id}` は含めない。値は hidden で送る）

| 入力項目 | 部品 | 備考 |
| --- | --- | --- |
| 商品ID | 表示用テキスト（readonly）＋ hidden | 変更不可。hidden で値を送信 |
| 商品名 | `type="text"` | 必須・100文字以内 |
| 値段 | `type="number"` / `min="0"` | 必須・0以上 |
| 在庫 | `type="number"` / `min="0"` | 必須・0以上 |

#### 商品IDの扱い

`th:field` は `id` 属性も自動生成するため、readonly 欄と hidden の両方に `th:field="*{id}"` を書くと HTML の `id` 属性が重複する。次のように書き分ける。

- **hidden 側**（値の送信を担当）：`th:field="*{id}"`
- **表示用 readonly 欄**（表示のみ）：`th:value="*{id}"` ＋ `readonly` ＋ `name` 属性なし

`disabled` は使わない（値が送信されなくなるため）。

- 商品名・値段・在庫は登録画面と同じ構成（`th:field` ＋ `th:errors`）とする。
- 表示時、Controller が対象商品を Form に詰めて渡すため、初期値が入った状態で表示される。
- ボタン：「更新」（submit）、「戻る」（`@{/items}` へのリンク）。

### 6-7. static/js/common.js

- `DOMContentLoaded` 後に `data-confirm-delete` 属性を持つフォームを取得する。
- `submit` イベントで `confirm('この商品を削除します。よろしいですか？')` を表示し、キャンセル時は `preventDefault()` で送信を中止する。
- HTML 側に `onclick` を直書きしない。

### 6-8. static/css/style.css

- 表・ボタン・入力欄・メッセージ（成功＝緑系／エラー＝赤系）の最低限の見た目を整える。
- 外部 CSS フレームワークは使用しない。
- `static` 配下はコンテキストルート直下から配信されるため、参照パスに `static` を含めない（`/css/style.css`）。

## 7. 処理シーケンス

### 7-1. 一覧表示

```
ブラウザ → GET /items
  → ItemController#list
    → ItemService#findAll
      → ItemDao#findAll（SELECT ... ORDER BY id）
    ← List<Item>
  → Model に "items" を格納
← item/list.html を描画
```

### 7-2. 新規登録

```
ブラウザ → POST /items/add（ItemForm）
  → 入力チェック（BindingResult）
      NG → item/add.html を再表示（入力値とエラーを保持）
      OK ↓
  → ItemService#existsById(id)
      true → BindingResult に「商品IDの重複」を追加 → item/add.html を再表示
      false ↓
  → ItemService#register(form)  ※@Transactional
      → ItemDao#insert（INSERT）
  → RedirectAttributes に successMessage
← redirect:/items
```

### 7-3. 更新

```
ブラウザ → GET /items/edit/{id}
  → ItemService#findById(id)
      null → errorMessage を付けて redirect:/items
      有   → Item を ItemForm に詰めて item/edit.html を描画

ブラウザ → POST /items/edit（ItemForm）
  → 入力チェック
      NG → item/edit.html を再表示
      OK ↓
  → ItemService#update(form)  ※@Transactional
      → ItemDao#update（UPDATE、更新件数 0 なら false）
  → 成否に応じて successMessage / errorMessage
← redirect:/items
```

### 7-4. 削除

```
ブラウザ（confirm でユーザー確認）→ POST /items/delete/{id}
  → ItemService#delete(id)  ※@Transactional
      → ItemDao#delete（DELETE、削除件数 0 なら false）
  → 成否に応じて successMessage / errorMessage
← redirect:/items
```

## 8. エラー処理方針

| 事象 | 挙動 |
| --- | --- |
| 入力チェックエラー | 元の画面を再表示。入力値を保持し、項目ごとにエラーメッセージを表示する。 |
| 商品IDの重複（登録時） | 登録画面を再表示し、商品ID 欄に「この商品IDは既に登録されています。」を表示する。 |
| 更新・削除対象が存在しない | 一覧画面へリダイレクトし、「対象の商品が見つかりませんでした。」を表示する。 |
| 更新画面を開く際に対象が存在しない | 一覧画面へリダイレクトし、同上のメッセージを表示する。 |
| 数値項目への文字入力 | `messages.properties` の `typeMismatch` メッセージを日本語で表示する。 |
| DB 接続不可などの想定外エラー | Spring 標準のエラーページを表示する（今回は独自のエラー画面は作成しない）。 |
